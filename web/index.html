    how the chat works
    Draw the change on this view (✎ edit: a shape with a name is a new module or function, an arrow is an import or a call, a deleted shape is a removal, text is a note), save, then code this: the drawing goes into ARCHITECTURE.md (the contract) and the agent builds it. improve the diagram asks the agent to review the contract; from document turns a design note into it. The agent may ask you a question with options. Nothing runs by itself.

        where the specification lives
        The specification lives in the repository, in formats tools open: openspec/specs/<capability>/spec.md (OpenSpec: requirements with SHALL, scenarios with WHEN and THEN) and features/*.feature (Gherkin). The agent writes and reviews them from the code, the contract and the pictures; every run starts from a button.
        
          
        
            
            
            
            
            
          
        
          
        
        
        
        
        
          
        what the flow shows
        Open a call flow (an entry point) to see its data flow: the steps in call order with their parameter and return types. Attach a mock input and mock storages; values are carried to parameters and properties of the same name. Nothing is run.

        Agents
        
      
        The coding agents the Chat tab runs. One that is found by its name needs nothing here. Place its program when it is somewhere else, and name a model when its own is not the one you want. Every change is kept at once.
        
      
        
      
        
        add an agent of your own
        
        Any command that takes the task as its last argument and prints the events of Claude Code (stream-json), Codex or OpenCode. Put a word with spaces in "double quotes".
        
        
        
          
          
          
          
          
        
        
      
        
      
        Keys
        
      
        A key is an environment variable named …_KEY or …_TOKEN; every agent run gets the keys set here. They are kept in the file above, on this computer and for you alone; the page is never sent a key back, only its last characters. OpenCode reads OPENROUTER_API_KEY for a model openrouter/…, and Claude Code runs on it with through OpenRouter ticked.
