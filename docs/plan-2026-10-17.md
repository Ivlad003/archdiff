## Фаза B. Аналітика на наявному графі

### B1. Метрики зв'язаності й зачеплення (7.1)

- `src/metrics.ts` (шар views):

```ts
export interface ModuleMetrics { id; layer; ca; ce; instability; abstractness; distance; cohesion; lines; fns; callsIn; callsOut }
export interface LayerMetrics { name; modules; ca; ce; instability; abstractness; distance }
export function metricsOf(graph: Graph): { modules: ModuleMetrics[]; layers: LayerMetrics[] }
```

  - Ca = модулів репозиторію, що імпортують модуль (без type-only); Ce = модулів, які він імпортує (без пакетів); I = Ce/(Ca+Ce) (0 при 0/0); A = (types + interfaces + abstract classes) / усіх верхньорівневих декларацій; D = |A + I − 1|.
  - Зачеплення (LCOM-подібне): граф функцій модуля, ребро коли дві функції викликають одна одну або ділять спільний callee чи тип (`DeclFact.types`); cohesion = 1 − (компонент − 1)/(fns − 1), 1 для ≤1 функції.
  - Для шару: Ca/Ce між шарами, A — середнє зважене.
- View `metrics` (placed, таблиця як `matrix`: рядки — модулі за D спадно, колонки Ca Ce I A D coh lines; `metrics:<layer>` звужує); Mermaid `quadrantChart` (x = I, y = A, квадранти «zone of pain» / «main sequence» / «zone of uselessness»), auto для цього view; Markdown-таблиця.
- Overlay `instability`: тінь за I, підпис `I 0.8 · Ca 12`, помаранчева мітка коли I ≥ 0.7 і Ca ≥ 3 (нестабільні, на які спираються).
- CLI `archdiff metrics [dir] [--json] [--layer X]`; сторінка: `metrics` в OVERVIEWS, чекбокс overlay.
- Тести: фікстура `sample`: `src/db/store.ts` Ca=1 Ce=0 I=0; `src/routes/checkout.tsx` Ca=0 I=1; quadrant у `--mermaid quadrant`.

### B2. Цикли (7.2)

- `cycles:fns` — SCC над `graph.calls` (`call` і `ref`) між fn-вузлами; смуга на цикл, підпис з модулями; `cycle:<path>#<fn>` для одного.
- `--types`: опція `types` включає type-only імпорти в `cycles`, `cycle:`, `matrix` і малює їх пунктиром (`DiagramEdge.typeOnly?: true` → Excalidraw `dashed`, Mermaid `-.->`, draw.io dashed).
- Цикли шарів: перша смуга `layers` у `cycles`, коли SCC шарів ≥ 2: фігури `layer`, лінії з лічильниками; `reason`: «layers in a circle: a ⇄ b (3 + 1 imports)».
- Де різати: для кожного циклу мінімальний feedback arc set за вагою (вага ребра = кількість import-рядків): перебір підмножин за зростанням розміру для ≤ 12 ребер, інакше жадібний Eades–Lin–Smyth; вибрані ребра `diff: "removed"` з підписом `cut: 1 import`, у `reason` і Markdown «To break the cycle, remove: a → b (1 import)».
- Тести: polyglot `orders.rs ↔ store.rs` → підказка різати ребро з меншою вагою; синтетичний граф у юніт-тесті (цикл з 3 вузлів, одне ребро з вагою 3, два з 1 → ріжемо одне з 1).

### B3. Сховища за фактами (2.8), поріг hubs (2.9), intent для великого репо (2.3), правила як дані (5.3)

## Фаза C. Control-flow у фактах і стейт-машини

### C1. Нові факти (6, 2.10, 5.4)

- `src/extract/facts.ts`:

```ts
export interface StateFact { subject: string; kind: "assign" | "case" | "compare"; value: string; within: string | null; under?: string[]; line; col }
export interface MachineFact { name: string; library: string; initial?: string; states: string[]; transitions: { from: string; to: string; event: string }[]; line; col }
FileFacts.states?: StateFact[]; FileFacts.machines?: MachineFact[];
CallFact.guard?: { kind: "if" | "else" | "loop" | "case" | "try" | "catch" | "ternary"; text: string; id: number }
```

- TS/JS (`src/extract/ts.ts`) — як tree-sitter queries у новому `src/extract/queries.ts` (запити-константи + `captureAll(query, node)`), а не ручний обхід:
  - `STATES_QUERY`: `assignment_expression` з лівою частиною `identifier|member_expression` і правою `string|number|member_expression(enum)`; `switch_statement` з `switch_case` на літералі; `binary_expression` з `===|==|!==|!=` і літералом. `subject` — хвіст member-ланцюга (`order.status` → `status`, `this.state` → `this.state`); `under` — значення найближчого `switch_case`/`if`-порівняння того ж subject над присвоєнням.
  - `MACHINES_QUERY`: виклик `createMachine|setup(...).createMachine|Machine|new StateMachine` з об'єктним літералом: читаємо `id`, `initial`, `states.<name>.on.<EVENT>: "<target>"` (XState v4/v5, `target:`), `transitions: [{ name, from, to }]` (javascript-state-machine), `states:[…]` масиви рядків.
  - `guard`: під час `declCalls` для кожного виклику — найближчий предок серед `if_statement` (consequence/alternative → `if`/`else`), `for|while|do|for_in` → `loop`, `switch_case` → `case`, `try`/`catch`, `ternary`; `id` = startIndex того оператора, `text` = умова (≤ 60 символів).
- Python (`src/extract/python.ts`): `self.state = "x"`, `if self.state == "x"`, `match self.state: case "x"`; `transitions.Machine(states=[...], transitions=[...])`; guard для `if/elif/else/for/while/try`.
- Rust/PHP: лише `machines` через `match self.state { State::A => … }` + `self.state = State::B` (Rust) і `$this->status = '…'`/`switch` (PHP), коли час дозволить; інакше документуємо як наступний крок.
- `EXTRACTOR_VERSION` → хеш джерел екстрактора (фаза E), кеш інвалідовується сам.
- Тести `tests/extract.test.ts`: сніпети на кожну мову → очікувані `states`, `machines`, `guard`.

### C2. Стейт-машини як граф і картинки (6)

- `src/machines.ts` (views): `machinesOf(analysis): Machine[]`, `Machine { id: "machine:<path>#<name>"; name; module; kind: "explicit" | "implicit"; initial?; states: { name; declared: boolean }[]; transitions: { from; to; event?; fn?; line }[]; note }`.
  - Неявна машина = (модуль, subject) з ≥ 2 значеннями і хоча б одним `assign`; переходи: `assign` з `under` → з кожного `under` у значення (підпис — функція); `assign` без `under` → `* → value` (пунктир); значення з union-типу / enum модуля, яких ніхто не присвоює — `declared` без присвоєння (planned, пунктир).

### D3. Mix із класами (2.4), смуги як колонки (2.5), split (2.6)

- `expandInPlace`: функції з `parent` ідуть у смугу `inside:<module>#<Class>` (підпис `Class (inside module)`), решта — `inside:<module>`; Markdown групує по смугах.

- Тести: `--expand` з класом → смуга класу; `--lanes columns` → діапазони x смуг не перетинаються, інваріант роутера тримається (routing test на `modules`).

### D4. Позиції при ручних фігурах (1.2) і вільний роутер (1.3)

- `layout`: прохід `avoidManual`: обчислена фігура, що перетинає ручну (з полем 12 px), зсувається вниз по своїй колонці на `gridH` до вільного місця; смуги розширюються. Інваріант у routing test: жодні дві фігури не перетинаються при часткових `positions`.
- `src/export/route-free.ts`: `routeFree(diagram): Map<DiagramEdge, Point[]>`: координати сітки = межі фігур ± 16 px і середини проміжків; вузли сітки поза роздутими фігурами; A* з вартістю = довжина + 30·повороти + 8·зайнятість сегмента; порти — середина правої/лівої сторони (або верх/низ, коли ціль над/під); `routeEdges(diagram, { free })` обирає вільний роутер, коли є ручні позиції (сервер: збережений малюнок) або коли `columnsOf` дає більше ніж 30 % зворотних ребер. Property-тест: 200 випадкових розкладок по 8–25 фігур → жодна лінія крізь фігуру.

### D5. Реальна симуляція (1.1)

- Межі: TS/JS, функція верхнього рівня (або експортований метод через інстанс не підтримується в v1), лише Node 22.18+.
- `src/run.ts` (views): `runFlow(analysis, entry, { input, storages, timeoutMs })` → `RunResult { steps: { id; order }[]; storageCalls: { module; member; args }[]; result?: unknown; error?: string; ms }`:
  1. Батько обчислює точки інструментування всіх модулів проєкту через `functionBodies` (`src/extract/bodies.ts`): `file → [{ id, bodyStart, expression: boolean }]`.
  2. Запускає `node --experimental-permission --allow-fs-read=* --import <archdiff>/dist/run/register.mjs <archdiff>/dist/run/harness.mjs` у `root` з даними через `module.register(url, { data })`: `resolve` перенаправляє пакети-сховища (таблиця `STORAGE_PACKAGES` + `node:fs` для запису + `fetch`) на `archdiff-mock:<name>`; `load` для `archdiff-mock:` віддає Proxy-модуль, що записує виклики і відповідає з мок-контенту (`query → { rows }`, `readFileSync → content.files[path]`, інакше `undefined`); для файлів проєкту вставляє `__archdiff.enter("<id>")` на початок тіла (`=> (enter(id), expr)` для виразів), знімає типи `module.stripTypeScriptTypes(code, { mode: "transform" })`.
  3. Harness імпортує entry, добирає аргументи за іменами параметрів із `input`, викликає, чекає Promise, пише JSON-рядки подій у stdout; `fetch` замінено рекордером (мережа заборонена).
- CLI `archdiff run <calls:view> [--input JSON] [--storage path=JSON] [--timeout ms] [--json]`; API `POST /api/flow/run`; Flow tab: кнопка «▶ run» поруч із «▶ play», підсвітка на канвасі: пройдені кроки зелені, передбачені але не пройдені сірі, несподівані сині; список викликів сховищ.
- Тест: `sample` → `archdiff run calls:src/lib/orders.ts#placeOrder --input '{"order": {...}}'` з моком `node:fs` → кроки містять `src/db/store.ts#save`, без запису на диск (перевірка, що файл не з'явився).
- Ризики: permission model + loader hooks (перевірити першим на smoke; якщо `--experimental-permission` блокує hooks — запуск без нього, але з `cwd` у тимчасовій копії репозиторію); TS-синтаксис, якого `transform` не знімає (`enum const`) — повідомлення «cannot run: …» без падіння.
