## What was fixed in this pass

1. Members of a class that extends a package's class (`$this->assertSame` in a PHPUnit test, `this.setState` in a React component) are the package's calls, not blind spots.
2. A `main` is an entry whether exported or not (Rust, Python); the uncalled public methods of controller-, handler-, middleware-, command-, job-, listener- and route-like modules are entries ("the framework calls them"); a package.json's `main`, `module`, `bin`, `exports["."]` — or `index.js` without any — names the library's entry file.
3. CommonJS: chained `exports = module.exports = f`; `module.exports = require("./x")` re-exports every name; a module binding called as a function is the module's default.
4. Rust: a facade crate's `pub use grep_printer as printer` is followed from `grep::printer::X`; `use self::Kind::*` of the file's own enum is no dependency and no unresolved import.
5. The graph records every module's resolved exports once (`resolvedExports`), which the entry points use.
6. A file over the size limit stays a module (opaque); `.d.ts` files are analysed; `.js` may name `.d.ts`.
7. CLI: a directory as `--out`, extra arguments, a missing view subject, git's errors all answer in one plain line with exit 2.

## Live runs with Claude Code (the same day, later)

Two runs through the page with the real agent (`web --agent claude`), both on scratch copies:

1. **The sample fixture.** Drawn: a module `src/lib/refunds.ts` in the lib lane, a function `refund` beside `orders.ts`, an arrow orders → refunds, a note with the rule ("reject an amount above the order total; refunds.ts keeps a list in memory"). Claude read the task from the Chat tab, read the files, wrote `refunds.ts` (a `Refund` type, `recordRefund`, `listRefunds`) and `refund()` in `orders.ts` with the rule from the note, and reported `file:line`. `review --base HEAD`: modules +1, functions +4, imports +1 (orders → refunds), no new layer coupling — the task and nothing else. Transcript streamed live; task saved to `.archdiff/tasks/`.
2. **storefront-next-template (React Router).** Drawn on `dir:src/routes`: a route module `src/routes/_app.returns.tsx`, its `loader` (labelled `path#loader`), an arrow to `_app.about-us.tsx` as the pattern, a note (a static list, no dependency install, skip typecheck without node_modules). Claude wrote the file-based route with `loader`, `meta` and a default component in the project's style and explained what differed from the drawing (one file, not two; no test file). The views then listed `route _app.returns.tsx: loader` and `default` as entry points.

Found and fixed on the way: a saved element missing fields Excalidraw needs (a scene saved through the API) crashed the canvas on the next load — elements now pass through Excalidraw's `restoreElements`; `thinking_tokens` and other system events of Claude Code's stream showed as raw JSON — now one-line notes; a label `path#name` whose path has slashes was read as a module — `#` wins.

## Known limits found, not fixed

- Rust integration tests (`tests/*.rs`, each its own crate with `mod util;`) resolve `crate::util` nowhere: 22 unresolved imports in ripgrep. The resolver knows library and binary targets, not test targets.
- Slim without `vendor/` and with a `composer.json` only: 254 PSR names unresolved (reported as such); with `composer.lock` they would be packages. Prophecy and mock chains are `dynamic`, honestly.
- express's tests: `request(app).get('/').expect(...)` chains are `dynamic`; `describe`/`it` are globals. 58% is the library's own calls.
- Symlinks are skipped silently without git.
- The page was exercised through the API and two Playwright tests; the agent against a live Claude Code was not run in this pass (the fake agent stands in).
