Примітиви з контрабандою: ключі view (на дроті доречні, в процесі обходяться); ID `path#Class.member` (доречно; `#` перерізається у `excalidraw.ts:120`, `navigation.ts:67`, `views.ts:659`); `ref.id` як graph-ID-або-ключ (недоречно); ID смуг `inside:<module>`, `…#<Class>`, «rest»-фігури `<module>#(rest)` (`shape.ts:196-209`), що імітують ключі; матриця `row:`/`cell:`; `DiagramNode` як один інтерфейс із 18 kind і опціями «на kind» (`reason`, `count`, `heat`) — замаскований tagged union, `shapeOf` (`excalidraw.ts:97-104`) симптом. Union `View` — доречний (закрита множина, вичерпний switch).

### Глосарій для `CONTEXT.md` (термін — визначення; у дужках що не вживати)

Module — файл-джерело у шарі. Layer — названа множина модулів. Declaration — функція/клас/метод/тип графа, ID `path#Name` (не «node»). Gap — виклик, що не простежено, з причиною; Blind spot — gap усередині репозиторію (dynamic, unknown-member, interface); Hole — намальований gap. Entry point — декларація, з якої починається виконання. View — питання: kind + subject, `kind:subject`. Picture — `Diagram`, який view породив (у прозі не «view»/«diagram» впереміш). Shape — одна фігура картинки (не «node»). Line — одна лінія (стрілка). Lane — смуга фігур (group). Hub — модуль, який імпортує більшість картинки; бейдж. Fold — хвіст як «… N in dir/». Step — чистий Diagram → Diagram; Overlay — крок-маркування. Mix — модуль, відкритий на місці. Layout — розміщення. Scene — елементи Excalidraw. Drawing — збережена сцена з моками (не «layout»). Focus — view усього, що з'єднано; Dim — інструмент (не «focus»). Contract — розібраний ARCHITECTURE.md (`Intent`); Intent view — контракт проти коду; Exports view — нинішній `contract:`. Calls view — дерево викликів entry (не «flow»); Flow — його потік даних із моками; Run — виконання зі змокованими сховищами; Storage — те, що тримає дані. Machine; State — його стан (стан сторінки → Link). Logic — тіло як flowchart; Rule — один шлях до виходу (не «path»). Chain — лінії далі / між двома фігурами. Plan — що змінює малюнок; Task — Markdown, відданий агенту (не «prompt»); Run — один процес агента; Turn — питання + відповідь. Review; Mark — added/removed/changed/warning/planned. Project map — точки; Minimap — картинка в мініатюрі (не «graph»; Graph — аналіз).

### Рішення, варті ADR (усі три критерії: важко відкотити, дивно без контексту, реальний компроміс)

1. ARCHITECTURE.md — один Mermaid flowchart у Markdown — є контрактом і джерелом шарів. Відкинуто: окремий JSON-файл правил, `archdiff.json` як первинний (агенти читають і пишуть Markdown; на нього зав'язані `new`/`import`/`check`).
2. Виклики резолвляться синтаксично над tree-sitter власним резолвером; невідстежений виклик — gap, ніколи не вгаданий edge. Відкинуто: програма TypeScript / language server (швидкість, п'ять мов, без native-збірки проти точності).
3. Один `Diagram`, розкладений раз у TypeScript для всіх цілей; стрілки Excalidraw без прив'язки, зі своїми маршрутами (`excalidraw.ts:403-406`). Відкинуто: розкладка на ціль (elk/dagre/binding Excalidraw) — детермінізм і байт-стабільні експорти проти рідного редагування.
4. Ключі view та ID декларацій — читабельні рядки на кожному дроті (лінки, Markdown, теги, малюнки, customData). Відкинуто: непрозорі ID з довідником — стабільність між запусками і PR проти парсингу й колізій.
